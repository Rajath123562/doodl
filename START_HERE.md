# DOODL. V3 — Complete Antigravity engineering handoff

**Version:** V3 / 2026-11-22. **Purpose:** Convert the existing offline Doodl V2 concept into a real, polished, secure, public-launch-capable multiplayer web game through iterative implementation with Google Antigravity.

## What you have, what you do NOT have

**Included:** detailed game-design/product specification, original offline UI reference, 11+ high-resolution visual references, a main agent instruction prompt, phase-by-phase execution prompts, 30 topic-specific engineering/design docs, contracts, risk registers, release criteria, QA tests, and a package self-auditor.

**Not included:** implemented networked game/backend, real matchmaking, deployed public URL, cloud credentials, guaranteed legal compliance, verified production security, measured load testing or a promise of bug-free operation. Antigravity must deliver and verify these separately.

## Fast start on Windows 11 (Google Antigravity)

1. Download/extract `DOODL_Antigravity_Production_Build_Kit_V3.zip` to e.g. `C:\Projects\doodl-v3`. **Open the extracted root** as Antigravity workspace, not just the HTML file.
2. Confirm Node.js (current LTS recommended), npm, Git and Chromium are usable. Check Cloudflare plugin/tool versions against official docs; never silently downgrade system tools.
3. Open `reference/demo-v2/index.html` locally in Edge/Chrome to view the offline appearance. Preview screenshots under `reference/demo-v2/previews/`; these are mocks/reference only.
4. Run `python tools/verify_package.py` and `python tools/review_kit.py` from this folder; `python` may need `py -3` on Windows. These verify **handoff integrity only**.
5. Copy **the entire text** of `prompts/00_MASTER_BUILD_PROMPT.md` into Antigravity. It tells Antigravity to read the workspace rather than expecting everything in chat memory.
6. For long projects, use `prompts/PHASE_00_AUDIT_AND_PLAN.md`, then all numbered phase prompts in order. Request actual code, runnable tests, UI screenshots, and `GO/NO-GO` phase reports. No fake online rooms.
7. Do not enter Cloudflare secrets into agent chat. Allow the agent to generate local source, test it, and then authorize staging deployment through the Cloudflare login flow when ready.
8. Do not invite the public until `checklists/PRODUCTION_SIGNOFF.md` is complete and `prompts/FINAL_RELEASE_AUDIT.md` returns `GO` backed by real evidence.

## Operating rules

- Free-first, no paid integrations without permission, no hidden costs or promises of unlimited free hosting.
- Production-ready is a **reviewed and measured release decision**. Documents cannot guarantee bug-free software.
- P0 is verified core multiplayer, P1 is complete user-facing V2 feature parity, P2 is advanced modes. Claim the exact tier completed, not the full vision if items remain missing.
- Preserve the original, delightful, professional aesthetic without copying another game's source, artwork or trademark.
- Ship on web first with strong desktop/mobile keyboard/pointer/touch support and accessibility.
- English word packs first; Hindi/Kannada packs require qualified language review before release.
- Private game invitation links must not be discoverable through public search or reveal credential secrets.
- Every event is validated on the server. No client-awarded score or guessed word leakage.

## Known limitations at handoff

This archive was statically audited for contents, links and file integrity. **No WebSocket multiplayer stack has been implemented or end-to-end tested here.** Files in `reference/` are a simulated clickable demo, not proof of release. See `docs/AUDIT_PREVIOUS_KIT.md` for gaps corrected and remaining real implementation risks.
