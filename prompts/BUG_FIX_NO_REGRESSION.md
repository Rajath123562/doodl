# Antigravity strict defect-remediation instruction

You are debugging the existing DOODL app, not redesigning/restarting it. Read `AGENTS.md`, symptom report, relevant contracts and current test trace. Reproduce the defect with a failing test or actual browser steps and record root cause; investigate logs and authoritative server state, not just UI. Fix the minimum appropriate abstraction, add a regression test that would fail before fix and pass after. Test negative/security cases if identity, score, word secrecy, permissions, WS events or storage changed. Run lint/typecheck/unit/integration/E2E/build as applicable, compare screenshots/mobile controls where UI changed. Do not suppress exceptions, delete tests, lower quality gates, leave TODO stubs or mark skipped as pass. Report defect ID, exact files, evidence, new failures and whether previous feature matrix remains green. If no actual runtime access say NOT VERIFIED. Update bug ledger and status. Never claim zero regressions without running full required suite.
