# DOODL. UI/UX — senior product design specification

## Reference materials

Inspect `reference/demo-v2/index.html` and `reference/demo-v2/previews/` visually. Treat as a **design and interaction reference**, not a mandatory pixel-for-pixel clone. Keep warmth, visual clarity, friendly identity and original avatar work. Improve deficiencies discovered through actual interaction tests; the end result should feel designed by an experienced consumer game team, not autogenerated generic admin UI.

## Design values

**Playful, not childish. Premium, not corporate. Fast, not frantic.** No template dashboard, busy gradients, gratuitous dark/neon glows, glassmorphism or giant decorative cards. Use motion to explain state, not to distract.

### Suggested initial tokens (validate contrast)

- Background `#F7F5F0`, surface `#FFFFFF`, primary text `#1F2330`, secondary text `#667084`, divider `#E7E7E2`.
- Primary coral `#FD7259` for primary actions; supporting mint `#BDF3D5`, lavender `#E8DDFF`, soft yellow `#FFF0B6` as game mode accents; do not use accent colors without semantic purpose.
- 8px spacing grid; card radius 16–22px; controls 10–14px radius; desktop 1360–1460px max content width; focus ring with tested contrast.
- Typography: e.g. Outfit headings and DM Sans UI if legally available, with system fallbacks; do not require network fonts for critical rendering. Headings 28–56px depending viewport; body 15–16px minimum, chat 14px if accessible.
- Motion: button press 100–150ms, page transitions 170–250ms, result celebrations <900ms, no continuous distraction; support `prefers-reduced-motion`.

## Product screens

**Home:** tiny brand top-left, avatar/settings top-right; strong one-line “Draw, guess, laugh” value, nickname, large Quick Play and Create Room, Join Code secondary; illustration depicting original vector characters; concise mode strip, daily challenge and gallery below. No login wall.

**Create room:** simple options: private/public, max players 2–12, round cycles 1–5, timer preset, word category, optional private password/custom words; show exact consequences and defaults; shareable link, copy button and join code accessible.

**Lobby:** host identity, max slots, players with avatar/ready/connection state, settings summary, invite link/copy, start disabled with reason until >=2 connected players, leave button. Permissioned host controls and join errors. Each player knows who else is actually connected.

**Classic game desktop:** persistent top bar with round indicator/time/word mask/network status; left narrow player leaderboard and avatars; **large central canvas**, compact tool row BELOW canvas only for drawer; right guessing/chat column with system notices and fixed input. No vertical overlays that steal pointer input. Spectator/guesser toolbar hidden, not fake-functional.

**Mobile game:** canvas first (fit within available viewport landscape or adaptive portrait); compact top row; chat as collapsible bottom sheet that does not cover canvas during a draw; guess input immediately reachable when guessing; toolbar in reachable horizontal scroll with visible affordance; scroll lock only on canvas. Avoid horizontal overflow at 320px width; support soft keyboard and mobile address-bar resizing.

**Word choice:** clear choices for drawer with a short countdown, visible to drawer only; others see “Player is choosing a word...” No text leakage into room state.

**Results:** show revealed word, player score delta, total ranking, quick next-round countdown, replay button if available; final result with winner but no excessive confetti or endless animation.

**Gallery:** only user-saved art; clear privacy state, local/cloud sync status, delete and download action with confirmation. No placeholder art shown as their own work.

**Daily:** one daily prompt, deadline, clear scoring rationale, offline and sync status. Do not imply AI judges aesthetic quality without actual service and evidence.

**Duels:** two equally weighted canvases side-by-side desktop, stacked carefully on mobile with explicit A/B navigation and target selection; guesses must explicitly target one lane. Visible fairness/timer/rules.

## States every screen needs

Loading, no room, joining, room full, connection lost, retrying, waiting for players, choosing word, current drawer, correct guess, eliminated/correct, timer ending, round ended, kicked, muted, match complete, unavailable mode, server quota error. No spinner that loops forever without guidance.

## Interaction quality

- Predictive/optimistic drawing on local canvas; use server reconciliation.
- Show real connected-state, reconnect ETA/attempt count, and action feedback.
- All buttons have clear labels, hover/focus/pressed/disabled/error states and keyboard semantics.
- Emoji reactions last briefly and are not critical to game comprehension.
- Settings, sound toggle, help, report and leave always accessible.
- Reduced motion, sufficient contrast, semantic headings, focus order, text equivalents for avatars, touch targets >=44 CSS px, screen reader announcements for round state and score changes.

## Required visual QA

Snapshots at desktop 1440×900 and 1280×720, tablet 768×1024, mobile 390×844 and 320×640 (plus landscape). Check canvas sizing, no cut-off controls, keyboard opening, contrast and no unexpected horizontal scroll. Include screenshot of disconnected state and winner state, not just homepage.
